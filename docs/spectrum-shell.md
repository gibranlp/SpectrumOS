# SpectrumShell

## Structural layer motion

Bars and the screen frame (including work-area reservation surfaces) have explicit `spectrum-bar`, `spectrum-frame` and `spectrum-frame-reservation` layer namespaces. Hyprland rules disable compositor animations for these surfaces and the shell-managed status/indicator/branding/Igor/hover surfaces, preventing a second animation from moving or fading their attachment geometry independently. Ordinary widgets keep their own shared slide/bounce motion on Top beneath Overlay bars/frame. The independent live ISO bar/network configuration applies equivalent rules to its own namespaces.

Window-title snapshots retain the last valid client array during transient query/JSON failures, so island bars do not collapse on failed reads. A valid empty client array still clears titles for an empty monitor.

The native [App Store](app-store.md) opens with **Super+Shift+U**, from More, or from its launcher entry. It searches Pacman repositories, AUR and Flatpak, with source/scope labels, package details, installation in a separate terminal with native password prompts and AUR review, persistent read-only activity and installed-app launching. **Super+K** lists the shortcut alphabetically as App Store.

While any MPRIS media player reports playback, or any application is fullscreen, the screensaver's idle monitor is disabled and an active screensaver dismisses. This checks every player, including one that is not selected for media keys or cannot be controlled. It covers windowed YouTube/movie playback when the app reports media state, and fullscreen playback even without media metadata. Native Wayland video inhibitors remain respected. The shell frame also holds a Wayland idle inhibitor during this activity to protect the existing Hypridle lock/display-off actions. Pausing playback and leaving fullscreen release the protection and restart the screensaver idle wait. This conservative policy also covers music and non-video fullscreen applications; a paused fullscreen app continues to inhibit idle until it leaves fullscreen.

Displays includes a **Screensaver** section. Start when idle defaults to enabled after three minutes, with 1, 2, 3, 5, 8, 10 and 15 minute presets. The screensaver shows continuous Matrix rain in the current theme colors. Independent streams have varied speeds, lengths and gaps, bright leading characters, changing symbols, subtle flicker and a faint background layer. It contains no wordmark, logo, branding sequence or effect cycling. Mouse movement, clicking, scrolling or pressing a key returns to the desktop.

The screensaver covers every connected physical monitor through temporary overlay surfaces. Its native Quickshell idle monitor respects Wayland idle inhibitors; Gaming and active screen/audio recording also suppress it. Keep Awake prevents system sleep and Hypridle actions while allowing the screensaver to appear after its configured idle delay. A session check prevents activation during an existing lock or system idle inhibitor other than the current user's SpectrumOS Keep Awake inhibitor and dismisses it when locking starts. Hyprlock continues to provide password protection. The shell creates a fresh native idle monitor when the timeout changes or an activity blocker clears. Run `python3 tests/check-screensaver-idle.py` inside an idle Wayland session to check timeout replacement and rearming against real compositor events. Settings live in `~/.config/spectrumos/screensaver.json`; enabled and timeout are configurable, and obsolete visual settings are ignored while unrelated stored keys are preserved.

The GPU samples Rezmason/matrix’s 57-symbol MSDF atlas for crisp Matrix glyphs, with native adaptations of its organic rain timing and distance-field reconstruction, a soft glyph halo, bright leading characters and smooth individual pulses. The current palette supplies the body and highlight colors. Source attribution and the upstream MIT license ship beside the atlas in `matrix-SOURCE.md` and `matrix-LICENSE.txt`. The Canvas fallback retains the system-font alphabet. No branding masks, particle formation or per-frame full-screen Canvas upload is needed on the GPU path. The Canvas fallback uses the same alphabet and continuous changing rain. The animation runs only while visible, with frame-synchronized updates targeting 60 updates per second and a logical rendering width capped at 1280 pixels. Update counts are not a measurement of presented FPS. Rebuild the shader with `/usr/lib/qt6/bin/qsb --qt6 -o configs/spectrum-shell/screensaver-matrix.frag.qsb configs/spectrum-shell/screensaver-matrix.frag`. Preview with `qs --path /usr/share/spectrumos/spectrum-shell ipc call spectrum-shell previewScreensaver matrix`; it closes after twenty seconds or on input. Normal widgets retain their existing stacking behind the bars.

## System updates

`Super+U` opens the native SpectrumOS update panel at the left center of the focused display. Opening it runs read-only safety checks for disk space, package-manager locks, interrupted transactions, and Btrfs restore-point support. Pending package counts come from the local database; the update itself refreshes repositories. Blockers disable the update buttons, and Check again repeats the checks.

Update everything performs a complete Arch and SpectrumOS repository upgrade, includes AUR packages when Paru is installed, applies ordered SpectrumOS migrations, and updates system and user Flatpak apps and runtimes. Successful package/migration/Flatpak completion determines success; the runner does not automatically run `spectrum doctor` or treat unrelated health findings as an update failure. Run `spectrum doctor` separately when diagnostics are needed. Update Arch + SpectrumOS packages skips AUR and Flatpak. Both open a terminal for explicit confirmation and authentication. The runner rechecks safety after confirmation and prevents concurrent SpectrumOS update windows. Pacman's pre-upgrade hook creates the system restore point and aborts if its creation fails. Flatpak failures are reported separately from successful system upgrades; user app data is not covered by a root-filesystem restore point. If the shell is unavailable, the shortcut opens the same confirmed terminal flow.

## Screen recorder

The recorder offers monitor, area, and window capture. Choose encoding settings before clicking a video source: MP4 or MKV (H.264/AAC), or WebM (VP9/Opus); Small file, Balanced, or High video quality; and Auto, 24, 30, or 60 fps. Auto uses frames as the screen changes. WebM may require more CPU. Audio comes from one desktop output or microphone, with 96, 128, 192, 256, or 320 kbps available when audio is enabled. Defaults are MP4, Balanced, Auto, 192 kbps, and no audio. Choices stay selected while the shell is running; changes apply to the next recording. Settings scroll on shorter displays.

Press Escape to dismiss an area or window selection. Stop and save finishes an active recording. Open recordings folder creates the directory if needed and opens it in Thunar. Files are saved under `$XDG_VIDEOS_DIR/Recordings`, falling back to `~/Videos/Recordings`.

The backend accepts `recorder-menu --start TARGET AUDIO [FORMAT QUALITY FPS AUDIO_KBPS]`, for example `recorder-menu --start area desktop mkv high 60 256`. Existing calls without encoding options use the defaults. Encoder options follow the [wf-recorder manual](https://github.com/ammen99/wf-recorder/blob/master/manpage/wf-recorder.1).

## Design reference

Bars, the display frame, and the multimedia notch stay on the compositor overlay layer. Widget panels and notification toasts use the top layer immediately below it. Their edge slide animations pass behind the shell surfaces, making panels appear to emerge from the bar or frame. Widget surfaces have `spectrum-widget-*` layer namespaces for inspection with `hyprctl layers`.

The display frame and expanding edge panels use the layout of [Caelestia Shell](https://github.com/caelestia-dots/shell/tree/20e625d6bf1a9d0bb7625a4bb814797d187b075d) as a design reference. An 8-pixel frame follows all four display edges, with 14 pixels reserved for window clearance on edges without a bar. The active bar reserves another 5 pixels beyond its visible size: 39 pixels at the top or 57 pixels at the left. Its curved joins move to the bottom of the top bar or the inside edge of the left bar, according to the selected layout. The launcher grows from its bottom edge, the dashboard opens from the top center, and the session rail joins the right edge. The frame and panel shells share one surface color without accent outlines. SpectrumOS retains its own actions, palette, app selection, and data adapters. No Caelestia source or assets are included in the package; its custom shape plugin is GPL-3.0, while `spectrum-desktop` is MIT licensed.

SpectrumShell is a Quickshell frontend. All monitors share the selected left or top bar position; the left bar is the default. Profiles are independent per monitor: focus a display and open Control Center with `Super+P`, then choose its Bar Profile. The heading identifies that monitor. Standard, Minimal, Detailed and Multimedia choices persist by connector name in `bar_profiles` inside `shell.json`, while `bar_position` remains shared. The existing `bar_profile` is the fallback for monitors without an override, so previous settings migrate without changing the desktop. Choose the position in Control Center → Shell Layout. The choice is saved in `$XDG_CONFIG_HOME/spectrumos/shell.json` (or `~/.config/spectrumos/shell.json`). The top bar is 34 pixels high, centers its clock, and retains its status and tray controls. Its Standard, Detailed, and Multimedia profiles also apply to the 52-pixel left bar. Minimal hides the bar entirely and keeps only the surrounding frame, reserving 14 pixels on every edge. Widgets attach to the 8-pixel frame instead of a hidden bar, and remain accessible through their keyboard shortcuts; `Super+P` opens Control Center to change profiles. The selected top or left orientation still determines where audio and other bar widgets open. Detailed shows system telemetry; Multimedia shows media controls, a fixed-position song title, and a Cava visualizer. The left bar also provides workspaces, launcher, dashboard and notification buttons; Standard places the additional system, Control Center and session controls inside More. `Super+X` opens an icon-only session rail with lock, suspend, log out, restart, and power off. Moving the pointer to the right edge does not open it. Escape or a click outside closes the rail. Lock runs immediately; the other actions require a second click within eight seconds.

Control Center slides in from the left side of the focused display, directly beside the left bar when that layout is active. The notification panel slides in from the right. Their inner corners are rounded, while the outer edge stays joined to the display frame. The notification panel is 380 pixels wide; 350-pixel notification toasts anchor to the frame's right edge and remain available in either bar layout. Closed panels release keyboard focus and unmap their overlay surfaces after the exit animation. The Aa, audio, Wi-Fi, Bluetooth, display, and weather icons in either bar open separate widgets. They attach below the top bar at the upper right or beside the left bar at the lower left, with curved shoulders at the join. Typography offers global font size, monospace family, and keyboard layout; audio offers volume and output/input devices; Wi-Fi offers connection state, addresses, nearby networks, and network management; Bluetooth offers power, scanning, and device connection. Device choices use `control-adapter`, Wi-Fi uses `network-adapter`, and typography uses `font-family-menu`, `font-size-menu`, and `keyboard-layout`. `Super+K` opens the keyboard shortcuts panel as a quick-access menu: click an entry, or select it with Up/Down and press Enter, to run the matching action. Workspace numbers and directional window controls have individual entries. The panel closes before launching the action, so window operations apply to the desktop window. Control Center is a single settings page for window layout and style, shell bar layout, workspace icons, and theme colors. Workspace icon choices include Kanji Numbers and seven state-based icon sets; Pac-Man shows Pac-Man on the active desktop, a ghost on one with windows, and a dot on an empty desktop. Its wallpaper preview and Browse button have been removed; Gowall filters remain at the bottom, and the wallpaper browser remains available through `Super+W`. The former combined Quick Controls panel has also been removed. Saved and open Wi-Fi networks connect directly; a secured new network prompts for a password. **Manage networks** opens the existing workflow and **Edit connections** opens NetworkManager's editor for IP, DNS, and other profile settings.

SpectrumShell is the only packaged Control Center. If it is unavailable, `spectrum-shell-open control` opens the maintained Wofi panel. The retired Eww service, UI files, and package dependency are excluded from new installations and the ISO staging path.

## Retired frontends

SpectrumShell owns bars, widgets, launchers, and notifications. Desktop package upgrades replace Eww, Wofi, Waybar, and Dunst, remove their retired configuration directories, and mask their user services through `spectrum-desktop-cleanup`. The same cleanup runs during local user adoption. Helpers named `waybar-widgets`, `waybar-cava`, and `waybar-workspace-icons` remain shared backends for the native shell; they do not launch Waybar. Personal workspace-icon preferences remain intact.

Shell attachments use `ShellGeometry.qml` for the 18-pixel outward radius and 8-pixel frame thickness. `ShellCorner.qml` draws one circular shape, mirrored for each direction; `ShellSurface.qml` squares attached edges and places the joins at their tangent points. Bar widgets attach to the top and right edges in the top layout, or the left and bottom edges in the left layout. Other attached panels and notification popups use the same geometry. Detached pickers retain their ordinary rounded corners. Notification stacks leave room for the shell corner before the first popup and an 8-pixel gap between adjacent outward curves.

`ShellMotion.qml` slides complete surfaces, including their outward curves, over 300 ms using a shared progress value. Destination coordinates remain bound to the layout without position animations, so hidden panels stay beyond their intended edge as their size or screen changes. Control Center, Recorder, Updates, and Shortcuts enter from the left; bar widgets enter from the top with a top bar and from the left with a left bar. Bottom-center panels, the launcher, and wallpapers enter from the bottom; top-center panels enter from the top. Notification popups and the history panel enter from the right. Closing reverses the same slide and keeps the overlay visible until it finishes. Popup notifications use a stable list model and a fixed overlay height so adding or removing one does not restart or resize the others. Recorder and Updates keep at least the frame thickness as their left inset, including with a top bar. Run the motion checks with `QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software /usr/lib/qt6/bin/qmltestrunner -input tests/qml/tst_ShellMotion.qml`.


Igor is SpectrumOS's official mascot, adapted from the original memorial illustration in `igor.svg`. ## Gaming profile

Open Control Center with `Super+P` and select **Gaming** under Bar Profile. Gaming applies to every monitor: bars, frame, desktop logo, mascot, recording overlay and notification toasts disappear, and the frame releases all reserved workspace space. Recording continues if already active. Widgets remain available through their existing shortcuts, open immediately without animations, and attach directly to the display edges. The top-center hover target remains available to open the dashboard. The audio visualizer and automatic mascot visits stop. UKVM follows the same edge placement and animation override.

GameMode-aware games and running Steam game processes activate the Gaming profile automatically, usually within one polling interval. This temporarily overrides every monitor without rewriting its saved profile. When the last GameMode client exits, each monitor returns to its previous profile and the GameMode power hook restores the previous power mode. Opening Steam alone does not trigger Gaming. Nonzero `SteamAppId` or `SteamGameId` process environments identify running Steam games, including Proton titles, without per-game launch options. Performance power mode by itself does not activate the Gaming bar profile.

`spectrum-gaming-session` keeps a verified GameMode client registered while Gaming is selected, requests the available Performance power profile, disables Hyprland animations and reapplies that override after compositor configuration reloads. Control Center displays activation errors. GameMode is a required desktop dependency; games can still use `gamemoderun` for their own process-specific optimizations. No overclocking or GPU policy is added by Spectrum.

External GameMode detection observes existing clients. Steam game detection holds a Spectrum GameMode client while game processes exist; that client is excluded from external detection, so Spectrum cannot keep a finished game session alive. Compositor animations are restored when automatic Gaming ends, and UKVM follows the same temporary override. If you leave Gaming or select another bar profile while a game is still active, automatic activation stays suspended until all GameMode clients exit; the next gaming session can activate it again. A manually selected Gaming profile stays active until you leave it.

Use **Leave Gaming · Restore previous profiles** in Control Center to restore all saved monitor profiles, logo, mascot and bounce preferences. Selecting another profile also leaves Gaming and applies that selection to the current monitor. Hyprland animations and the prior power mode are restored when the Gaming session ends; other registered GameMode clients retain their performance request. The session also releases its requests on normal shell shutdown. Profile state remains under `~/.config/spectrumos/shell.json`; the command-line adapter supports `set-profile gaming` and `set-gaming off`, and the shell watches external preference changes.

Local verification on October 17 used real GameMode clients and both connected monitors. Two overlapping clients kept Gaming active until the final exit; each monitor then returned to its Detailed or Minimal profile. Balanced and Power saving both switched to Performance and restored correctly. Explicit Leave Gaming stayed in effect for the current session and automatic activation returned for the next session. The original Performance mode, animation setting and personal preferences were restored after testing. The shell loaded without configuration errors. Tests used controlled GameMode clients rather than launching a game title.

## HotKey

**Super+H** opens HotKey; the **Super+K** keyboard shortcuts widget also lists it.
Type a key or sequence (`2`, `234`, `abc`) or add a named key from the selector.
Set the interval in milliseconds and type or press a toggle shortcut, for example
**2** or **Control+Shift+2**, then click **Add**. Use **Record** to capture a single key or chord. Each entry can be edited, removed,
started or stopped independently. **Stop all** stops every running entry directly.

For `234` at 1000 ms, HotKey sends `2 → 3 → 4`, waits 1000 ms after the final release, then repeats the full sequence. Keys within a sequence follow as soon as delivery completes. A single `2` with a 50 ms interval repeats with a 50 ms pause. Press the assigned shortcut once to start,
then again to stop. Shortcuts trigger on press without automatic key-repeat; starts wait 250 ms so you can
release the shortcut keys. Clicking Start dismisses the widget so keys reach the
focused application. Closing the widget keeps running sequences active.

Rules persist privately at `$XDG_CONFIG_HOME/spectrumos/hotkey.json`; active state
is never persisted. Login/restart restores shortcuts with every sequence stopped.
The graphical-session user service uses Hyprland's native Lua binding API and
one persistent native Wayland virtual keyboard with a standard XKB keymap. The small C helper isolates the Wayland library API; Python retains rule validation and scheduling. No privileged input devices or X11 fallback
are used. Shortcuts already assigned to another desktop action are rejected.
HotKey toggle bindings exclude the generated Wayland keyboard through [Hyprland device filtering](https://wiki.hypr.land/Configuring/Basics/Binds/#per-device-binds), so repeating the same key as the shortcut cannot toggle itself or consume generated presses. Physical shortcut presses are consumed as toggle commands. Compositor shortcut inhibition remains effective; this does not change UKVM.

Supported sequences contain letters, numbers and named keys (`[Enter]`, `[Space]`,
`[Tab]`, arrows, navigation keys and F1–F24). Up to 32 rules and 32 keys per rule
are supported, with intervals of 10–60000 ms and a combined active limit of 200
keys/second, counting every key in each sequence. Each press includes a release. Delivery is best effort: late ticks
are skipped without accumulating input. A slow/failed shared Wayland keyboard stops all active rules. Lock detection stops active rules without resuming on unlock;
logout/service shutdown stops all presses and removes owned shortcut bindings.
There is one keyboard helper for all active rules, one outstanding press and no queued future presses. No subprocess or keymap is created per key. Ctrl+Alt+Pause stops all; the widget shows numeric toggle and sent-press counters for diagnosis.

The backend accepts only bounded local commands over a private runtime socket;
text never becomes a shell command or unrestricted Lua. Tests use fake typing and
compositor tools rather than injecting into the real desktop. Physical shortcut
and application acceptance remain user checks after deployment.

## Questline workspace autosave

The widget remembers its active tab, campaign/project, selected task or scroll, step editor, text cursor, editor/list/detail scroll positions, and focus preferences. Closing it, opening another utility, switching tabs, or restarting SpectrumShell restores that workspace. The shared workspace lives once per shell, so opening Questline on another monitor uses the latest saved view.

Task, step, sidequest, scroll, and treasury forms save valid edits after a short typing pause and flush when closed or left. Save and Cancel have been replaced with Back and an autosave status. Back keeps the edits. Incomplete titles, dates, scroll content, and treasury amounts remain local drafts until valid. Unfinished drafts can be resumed from their tab. A failed write keeps the editor and draft; Retry is explicit. Task completion, deletion, watering, and starting/resetting focus sessions still require their respective actions.

Private draft/navigation state is atomically written with mode 0600 under `$XDG_STATE_HOME/spectrumos/questline-widget.json`, defaulting to `~/.local/state/spectrumos/questline-widget.json`. Autosave requests are serialized with other widget actions. New items receive stable autosave UUIDs before mutation, allowing an interrupted creation to resume against the same row rather than duplicate it. Saving a scroll in the background does not repeatedly award edit XP; explicit edits in the full app keep their existing XP behavior.

The local deployment includes the matching Questline `shell_api.rs` changes and updated binaries. The next packaged release must include that Questline API before publishing the widget autosave update; the existing downloaded Questline release artifact does not contain those API changes. This task does not build an ISO or publish packages.

Verification: `tests/run_questline_workspace.py` exercises the real QML panel with isolated mock backends, including close/reopen during creation and restoration in a fresh Quickshell process. `tests/qml/tst_QuestlineDrafts.qml` covers background edits, failures, queuing, and resumption. `tests/test_questline_widget_state.py` verifies atomic private storage. Run `tests/test_questline_autosave.py` with `QUESTLINE_TEST_BINARY` pointing to the matching binary to verify canonical writes, duplicate prevention, and XP behavior against temporary databases.

### Questline tree rendering

The Tree tab draws Questline's colored procedural cells into a `Canvas.Image` texture. It uses the same `shell-tree` output as the terminal application, removes empty margins, centers the result, and fits both the available width and height without enlarging text beyond 28 pixels. The shell retains its normal hardware renderer; only the tree's glyphs are rasterized into the canvas. The adapter exposes `bonsai_rows` alongside the existing HTML field for compatibility.

This avoids sending the tree's many individually colored rich-text glyphs through Qt's text batching path. Qt 6.12.0 / Quickshell 0.3.2 crashes in `QSGBatchRenderer::Renderer::prepareAlphaBatches()` were observed on the reference PC and reported on a second AMD system. The second system could open the original tree with `QT_QUICK_BACKEND=software`; changing only `QSG_RENDER_LOOP=basic` did not prevent its crash. The canvas change is a targeted mitigation, with accelerated and software rendering tests; confirmation on the second PC remains pending. No global software-rendering default is introduced.

Run the tree pixel and lifecycle checks with:

```bash
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software /usr/lib/qt6/bin/qmltestrunner -input tests/qml/tst_QuestlineTree.qml
```

Display scaling offers 1×, 1.25×, 1.5×, 1.75× and 2× through the same per-monitor scale control. The screensaver backend accepts delays from 30 to 900 seconds and preserves unrelated settings.

Calculator (`Super+C`) has a keypad, Ans, sign change, backspace, Copy and AC. Enter or = evaluates. After a result, type an operator and the next operand (or click the operator), then evaluate again; `100 + 20`, then `× 2`, then `+ 15%` produces 276. ## Widget memory lifecycle

Heavy content in Control Center, Favorites, App Store, and selected BarWidget and Utility pages is created synchronously on first use and retained for the rest of the shell session. The shared CachedContent loader separates first-use creation from page visibility: closing a panel keeps its contents present through the existing motion, while reopening preserves forms and calculator results. Frequent bar controls and shared background managers remain immediately available.

This trades some first-opening work for a smaller startup baseline; subsequent openings reuse the same instance. Savings decrease as more tools are visited. The shell still creates other panel contents per monitor, so this is an initial optimization rather than a complete lazy-panel conversion. Interactive timing and full widget acceptance remain pending under the owner's test pause.

Questline's main editor/detail/onboarding interface is also retained on first use. Dashboard refreshes can fetch Questline data without creating that interface or overwriting a saved view with empty form values. Opening the widget, a due item, a quick task, a quick note, or an explicit tab action prepares the interface before accessing its fields. The Dashboard calendar is independently created on the Dashboard's first opening.

The wallpaper gallery is created on first opening and keeps its selection and decoded preview cache for reopening. Images request a decode size based on the thumbnail dimensions and current device pixel ratio instead of decoding full wallpaper resolution. Wallpaper application still uses the original file.

A focused read-only runtime check opened and closed ten widgets four times on DP-1. PSS increased from about 449 MiB before first use to about 503 MiB after caches warmed; closed readings across the four rounds stayed between 497 and 504 MiB. ## Shell allocator policy

The launcher defaults `MALLOC_CONF` to `thp:never` for the jemalloc-linked Quickshell process, preserving any explicitly supplied value, including an empty value. This requests normal-sized pages for allocations managed by jemalloc; it does not change the kernel's huge-page policy or other running services. Driver/runtime mappings outside jemalloc may still use huge pages. The default threaded Qt renderer remains unchanged. See the [jemalloc option reference](https://jemalloc.net/jemalloc.3.html#opt.thp).

On the current two-monitor AMD system, initial PSS was about 444 MiB with the default allocation policy and 375 MiB with this setting. After three rounds opening and closing ten widgets, PSS was about 406–409 MiB, compared with 497–504 MiB in the earlier default-policy rounds. Median IPC command time stayed about 28 ms; this measures command completion, not first paint or animation frame rate. Sampled outer frame pixels were identical before and after. These observations do not establish performance on every GPU or absence of long-term memory growth. Evidence: `artifacts/shell-render-memory-20261024`.

## Search locations

**Super + S** opens file search. Choose Home, a standard home folder, a mounted drive, or a recent location from the location dropdown. To search a subfolder such as `/media/Music`, type its absolute path in the folder field and press **Use** or Enter. `~/Music` is accepted too. Then enter at least two characters in the filename search field.

The selected folder is remembered across widget openings and shell restarts in `$XDG_STATE_HOME/spectrumos/search.json` (normally `~/.local/state/spectrumos/search.json`). The default is Home; unlike the older widget's standard-folder-only search, this covers the visible home tree. Drives under `/media`, `/mnt` and `/run/media` appear when mounted. Other readable folders remain available through the path field. An unavailable saved drive produces an error rather than a silent fallback to Home; select another location to continue.

Searches match filenames case-insensitively, skip hidden entries and directory symlinks, return up to 60 results, and use an eight-second traversal budget with partial-result feedback. Changing the query/location or closing the widget cancels the previous worker; request IDs discard stale results. Enter opens the selected result and arrow keys move through results. There is no background index or polling. The existing panel geometry, monitor routing and stacking are preserved, and the component is retained on first use.

The legacy `spectrum-shell-tools search QUERY` array interface keeps its previous behavior for other callers. The widget uses separate structured `search-state`, `search-root PATH`, and `search-json JSON` commands. Developer verification is limited to `python3 -m unittest tests.test_spectrum_shell_tools.SearchLocationTests` and `scripts/check-file-search-ui`, both using temporary folders/fake UI backends.
