# Printing, transfers, and network sharing

Evolution and KDE Connect are required in both Full and Lean installations. KDE Connect includes `kdeconnect-indicator`; SpectrumOS starts it through the session's XDG autostart manager so phone access appears in the top and left bar trays. The daemon uses KDE Connect's own D-Bus/XDG startup. Pair a phone through KDE Connect to use its multimedia controls; pairing remains an explicit user action.

The desktop profile includes `transmission-cli` for terminal and remote BitTorrent workflows. Spectrum's Zsh defaults create `~/Downloads` when needed and pass it as the CLI's default destination; a later explicit `-w` argument can override that location. User adoption also enables the system Transmission daemon, grants its service account narrowly scoped ACL access to the target user's home and Downloads directory, and configures the daemon's RPC default destination as `~/Downloads`. Persistent systemd overrides reapply the destination and ACLs whenever the daemon starts and limit startup to 30 seconds so a stalled daemon cannot indefinitely hold up the graphical login target. Downloads added through `transmission-remote` therefore use the same destination as `transmission-cli`. Daemon-created files remain owned by the isolated `transmission` service account, while inherited user ACLs provide the target user with full management access. User adoption also repairs those ACLs recursively on older Transmission-owned downloads.

Printing uses CUPS with OpenPrinting filters, PostScript conversion, Gutenprint drivers, driverless IPP-over-USB support, Polkit-backed printer administration, SMB printer browsing, and Avahi discovery. SpectrumOS enables `cups.socket`, `cups-browsed.service`, and `avahi-daemon.service`; the CUPS daemon starts on demand. Printers can be managed from Control Center → Utilities → Printers.

Samba and the GVfs SMB backend provide server commands and network-share browsing in Thunar. Control Center → Utilities → Network shares opens the network browser. SpectrumOS installs a valid standalone, authenticated-only Samba baseline and a `sambashare` usershare group, but does not enable `smb.service` or publish a default share. Add the user to `sambashare`, create an explicit usershare with `net usershare`, set the corresponding Samba account password with `smbpasswd`, and then enable `smb.service`. Guest exports are disabled by default.
